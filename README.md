# Story Videos — генератор роликов в формате «ИСТОК»

Вертикальный ролик 9:16: закадровый рассказ, один и тот же персонаж во всех
сценах, пословные караоке-субтитры. Тема на входе — mp4 на выходе.

```
тема → сценарий (LLM)
     → референс-лист персонажа (1 картинка)
     → кейфреймы шотов (с этим референсом → лицо не «плывёт»)
     → озвучка ElevenLabs с ПОСЛОВНЫМИ таймкодами   ← длина озвучки = длина шота
     → image-to-video на каждый шот (Veo)
     → ASS-субтитры по таймкодам + сборка ffmpeg
     → out.mp4
```

Airtable и Telegram здесь намеренно нет — сначала обкатка через CLI.

---

## Быстрый старт

```bash
pip install -r requirements.txt          # нужен установленный ffmpeg с libass
cp .env.example .env                     # заполнить 3 значения
set -a && source .env && set +a

python3 cli.py doctor --render-test      # проверка окружения, БЕЗ ключей и денег
python3 _smoke_offline.py                # весь конвейер на заглушках, БЕЗ денег
```

`doctor --render-test` прожигает тестовые русские субтитры на цветной фон.
Если кириллица не квадратами и слова меняются — визуальный слой в порядке.

`_smoke_offline.py` гоняет весь `render()` с подменёнными API: проверяет порядок
шагов, инвариант длины шота, склейку и хронометраж. Именно здесь ловятся
поломки конвейера, а не в платном прогоне.

### Первый платный ролик

```bash
# 1. сценарий (дёшево — только текстовая модель)
python3 cli.py script --topic "история человека, который построил первую биржу" \
                      --lang ru -o s.json

# 2. посмотреть, что реально уйдёт в генерацию (бесплатно, офлайн)
python3 cli.py prompts s.json

# 3. рендер
python3 cli.py render s.json -o out.mp4
```

Или всё сразу: `python3 cli.py make --topic "..." -o out.mp4 --script-out s.json`

### Интонация: почему речь может звучать роботом

Речь синтезируется **одним запросом на весь текст** (`VOICE_MODE=whole`).
Это не оптимизация, а условие живой интонации: ElevenLabs на каждом вызове
ставит финальную интонацию и паузу, поэтому пошотовый синтез даёт не рассказ,
а набор оборванных фраз, склеенных встык. Никакой голос это не лечит.

Границы шотов после синтеза берутся из пословных таймкодов — рез идёт по
**середине паузы** между репликами, а не по последнему слову, иначе склейка
попадает на выдох и монтаж звучит рвано.

`VOICE_MODE=per_shot` оставлен только для отладки.

### Своя готовая озвучка

Если текст начитан своим голосом или прогнан через студию:

```bash
python3 cli.py render s.json --voice voice/my_take.mp3 -o out.mp4
```

Тайминги слов снимаются с этого файла через forced alignment ElevenLabs, сверяясь
со сценарным текстом. Поэтому и субтитры, и длины шотов подстраиваются под живую
речь — вручную ничего двигать не надо. На Railway то же самое даёт `VOICE_FILE`.

Текст для начитки берётся из `narration.txt` предыдущего прогона либо из
`cli.py fromtext`.

### Ролик без озвучки

`VOICE_ENABLED=false` — голос не синтезируется, ключи ElevenLabs не нужны.
Тайминги слов считаются из длины текста: караоке работает, ритм ровный вместо
живого. Всё остальное в конвейере не меняется, поэтому можно оценить кадры,
монтаж и субтитры, не оплачивая TTS, а потом включить голос и пересобрать.

Под такой ролик почти всегда нужна музыка (`MUSIC_PATH`) — иначе 30 секунд
идут в полной тишине.

### Бренд в кадре

Два независимых слоя, и путать их не надо:

**Нативный плейсмент** — имя рисует картиночная модель прямо на предмете сцены
(баннер над ареной, мышкоковрик, джерси, вывеска). Сценарист сам предлагает
подходящий предмет для каждого шота полем `brand_surface`, а `BRAND_SHOT_RATIO`
решает, в скольких шотах бренд появится — по умолчанию 60%, равномерно по
таймлайну, минуя первый шот. Сплошной плейсмент читается как реклама и убивает
эффект истории, ради которого формат и работает.

**Слоган на вывеске** (`BRAND_TAGLINE`) — короткая надпись в **верхней трети**
кадра: висячий баннер, световой короб, панель над дверью. Верх выбран потому,
что низ занят субтитрами, середина героем, и только там вывеска смотрится
естественно. Ставится реже имени (35% шотов): вывеска с сообщением — это уже
почти реклама, и в каждом втором кадре она сжигает доверие к истории.

Ограничение жанра: **чем длиннее строка, тем выше шанс опечатки.** Одно слово
выходит почти всегда, до 18 знаков — часто, фраза из пяти русских слов — почти
никогда. Латиница и цифры держатся лучше кириллицы. Рабочие варианты:
`MIN DEP 1 USDT`, `PLAY WITH CRYPTO`, `CRYPTO WINS`, `1 USDT`.

**Промо-плашка** (`PROMO_TEXT`) — накладывается ffmpeg'ом поверх готового видео.
Опечаток не бывает никогда. Сюда идёт всё, что обязано быть буквально точным:
промокод, оффер, домен. `|` = перенос строки.

```
BRAND_NAME=Coinplay
PROMO_TEXT=200 ФРИСПИНОВ|ПРОМОКОД COINPLAY
```

**Чего ждать честно:** картиночные модели врут в буквах. Часть кадров придёт с
опечаткой в названии — `Coinplav`, `Coinplai`, лишняя буква. Промпт требует
точного написания и запрещает любой другой текст в кадре, это сильно повышает
попадание, но не даёт гарантии. Планируй отбраковку: смотри кейфреймы в
`work/<папка>/keyframe_*.png` до того, как уйдут деньги на видео. Всё, что должно
быть точным на 100%, — только в промо-плашку.

### Почему герой может выйти статичным

Три места отвечают за то, живёт персонаж в кадре или стоит манекеном:

1. **Референс персонажа** фиксирует только лицо, причёску, телосложение и одежду.
   Промпт кейфрейма прямо запрещает копировать позу референса — иначе модель
   переносит вместе с лицом и стойку «руки по швам».
2. **`action`** у каждого шота — глагол, который герой делает прямо сейчас
   («вбивает клавиши», «продирается сквозь толпу»). Шот без действия читается
   как картонная фигура на фоне.
3. **`framing`** меняется от шота к шоту. Повторяющаяся средняя фронталка —
   самый быстрый способ сделать ролик похожим на генерацию. Если сценарист
   не заполнил поле, ракурсы раскладываются по кругу автоматически.

Если герой всё равно застывает, смотри `action` в сценарии: скорее всего там
«стоит» или «смотрит».

### Свой текст озвучки

Когда интонация, порядок фактов и ударения важны, писать текст должен человек.
Тогда LLM не трогает нарратив вообще — только придумывает картинку к каждой реплике.

```bash
python3 cli.py fromtext narration.txt --estimate    # разбивка и цена, без API
python3 cli.py fromtext narration.txt -o s.json --hook "как это придумали"
python3 cli.py render s.json -o out.mp4
```

`--estimate` показывает, на сколько шотов разобьётся текст, сколько выйдет
секунд и сколько шотов уйдёт в видеомодель — **до** любых трат. Полезно, потому
что длина ролика диктуется текстом: 124 слова это ~78 секунд, а не 30.

Разбивка делается кодом, а не моделью: по концам предложений, при
необходимости по запятым. Модель на длинном тексте теряет предложения и
перефразирует их, а здесь важна дословность.

На Railway то же самое даёт `NARRATION_FILE=examples/sushi_ru.txt`.

### Управление сюжетом

По умолчанию сюжет целиком выводится из `TOPIC` — LLM сам придумывает героя,
сцены и реплики. Это удобно для потока, но результат каждый раз новый.

Когда нужен предсказуемый ролик, порядок другой:

```bash
python3 cli.py script --topic "..." -o s.json   # сгенерировать
# открыть s.json, поправить руками: реплики, сцены, brand_surface
python3 cli.py render s.json -o out.mp4          # отрендерить именно это
```

На Railway то же самое даёт `SCRIPT_FILE=examples/night_server_ru.json` —
тогда `TOPIC` игнорируется и LLM не вызывается вообще. Коммитишь проверенный
сценарий в репо и рендеришь сколько нужно, получая один и тот же текст.

Промежуточный вариант — `EXTRA_DIRECTION`: тема остаётся за LLM, но ты
задаёшь рамку («герой — женщина», «действие в Латинской Америке», «без
упоминания денег»).

### Текст отдельно — озвучить чем угодно

Каждый рендер кладёт в рабочую папку три файла, независимо от `VOICE_ENABLED`:

| Файл | Зачем |
|---|---|
| `narration.txt` | текст для чтения: строка на шот + сколько секунд под неё отведено, плюс всё сплошняком для вставки в любой TTS |
| `narration.srt` | те же реплики с таймкодами — бросаешь в редактор и попадаешь в монтаж |
| `captions.srt` | пословные субтитры, ровно те, что прожжены в ролик — если захочешь переделать их в CapCut |

При `VOICE_ENABLED=false` на выходе получается немой монтаж плюс этот текст:
записываешь голос под тайминги из `narration.txt`, кладёшь дорожку поверх в
любом редакторе — и ничего пересобирать не нужно. На Railway все три файла
прилетают в Telegram следом за роликом.

### Итерации по субтитрам — бесплатно

Рабочая папка каждого рендера остаётся в `work/`. Поменял размер/позицию/шрифт
в `.env` — пережигай без повторной генерации картинок и видео:

```bash
CAPTION_SIZE_RATIO=0.095 python3 cli.py captions work/story_1712345678 -o v2.mp4
```

## Сколько это стоит

Ролик 30 сек = 8 шотов по 4 сек (`TARGET_DURATION_SEC` / `SHOT_TARGET_SEC`).

| Статья | Количество | Порядок цены |
|---|---|---|
| Сценарий (LLM) | 1 вызов | ~$0.02 |
| Картинки | 1 референс + 8 кейфреймов | ~$0.35 |
| Видео (Veo fast, 720p, без звука) | 8 × 4 сек = 32 сек | **~$4–5** |
| Видео (Veo standard) | те же 32 сек | ~$12–13 |
| ElevenLabs | ~30 сек речи | ~$0.05 |

**Итого ~$4.5–5.5 за ролик на fast-тарифе.** Цены видеомоделей меняются часто —
реальная стоимость каждой джобы приходит из API (`usage.cost`) и суммируется в
`video_cost` итогового JSON. Первый прогон покажет фактическую цифру.

### Темп речи — не трогать наугад

`WORDS_PER_SEC` определяет, сколько слов сценарист напишет в шот. Значение
замерено на русском ElevenLabs: **1.7 слова в секунду**. Если поставить больше,
ломается цепочка: реплики выходят длиннее шота → шот перерастает потолок клипа
видеомодели (8с) → `compose` добивает хвост замороженным кадром, и это видно.

Проверить на своём голосе просто: в логах есть `Озвучка шота N: XXс, YY слов`.
Делишь слова на секунды — получаешь свой реальный темп. Другой голос или
`ELEVEN_SPEED` его меняют.

### Как удешевить

Видео — примерно 95% чека, всё остальное копейки. Поэтому рычаги только вокруг него:

| Рычаг | Что делает | Экономия |
|---|---|---|
| `ANIMATE_RATIO=0.5` | половина шотов идёт зумом из кейфрейма вместо видеомодели | **~50%** |
| `ANIMATE_RATIO=0` | видеомодель не вызывается вообще, весь ролик зумом | **~95%** |
| `SHOT_TARGET_SEC=6` | 5 шотов на те же 30 секунд вместо 8 | ~37% |
| `TARGET_DURATION_SEC=20` | ролик короче | ~33% |
| `VIDEO_RESOLUTION=480p` | если модель поддерживает | зависит от модели |

`ANIMATE_RATIO` — самый выгодный: живое движение достаётся первому шоту (он
решает, досмотрят ли), последнему и смысловым поворотам, а проходные шоты держат
зум. На четырёх секундах с крупным словом поверх разницу почти не видно.

Рычаги складываются: `ANIMATE_RATIO=0.5` + `SHOT_TARGET_SEC=6` дают примерно
$1.5 вместо $5.

## Что настраивается

Всё через `.env`. Самое полезное:

| Переменная | Что делает |
|---|---|
| `TARGET_DURATION_SEC` / `SHOT_TARGET_SEC` | длина ролика и шота → число шотов |
| `WORDS_PER_SEC` | темп речи; менять только после замера по логам |
| `STYLE_PRESET` | `pixel_story` (как в референсе) / `anime_lofi` / `cinematic_doc` |
| `VIDEO_MODEL` | слаг видеомодели — **проверь через `cli.py models --filter veo`** |
| `CAPTION_SIZE_RATIO` | кегль субтитра как доля высоты кадра (0.088 снято с референса) |
| `HOOK_SIZE_RATIO` | кегль хука сверху; длинный текст ужимается сам |
| `CAPTION_MARGIN_V` | высота плашки над низом кадра |
| `CAPTION_CASE` | `lower` (как в референсе) / `upper` / `as_is` |
| `BRAND_NAME` / `BRAND_SHOT_RATIO` | имя бренда в сцене и доля шотов с ним |
| `BRAND_TAGLINE` / `BRAND_TAGLINE_RATIO` | слоган на вывеске вверху кадра, до ~18 знаков |
| `PROMO_TEXT` | плашка сверху наложением, `\|` = перенос строки |
| `CAPTION_MIN_SEC` | короче этого слова клеятся в пару («1994 году») |
| `ELEVEN_SPEED` | темп рассказчика, 0.7–1.2 |
| `OUTRO_HOLD_SEC` | сколько держать финальный кадр после последнего слова |
| `VOICE_ENABLED` | `false` = собрать без голоса, только субтитры и музыка |
| `VOICE_MODE` | `whole` = весь текст одним запросом (живая интонация) |
| `VOICE_FILE` | своя готовая озвучка; тайминги снимаются с неё |
| `MUSIC_PATH` | mp3-подложка; громкость — `MUSIC_VOLUME` |
| `XFADE_SEC` | 0 = жёсткие склейки как в референсе; 0.2–0.3 = мягкие |
| `ANIMATE_RATIO` | доля шотов через видеомодель; 0 = только зум |

Креативная часть — только `story/prompts.py`: стилевые пресеты, системный промпт
сценариста, сборщики промптов. Новый визуальный стиль = новая запись в
`STYLE_PRESETS`.

## Устройство

| Файл | Ответственность |
|---|---|
| `config.py` | все параметры и дефолты; ключи проверяются лениво |
| `story/prompts.py` | стили и все промпты |
| `story/script_writer.py` | LLM → JSON сценария + жёсткая нормализация ответа |
| `story/visuals.py` | референс персонажа, кейфреймы, image-to-video, цепочка фолбэков |
| `story/voice.py` | ElevenLabs with-timestamps → wav + пословные тайминги |
| `story/captions.py` | ASS-караоке (группировка коротких слов, «пых» масштабом) |
| `story/compose.py` | нормализация, склейка, прожиг субтитров, микс |
| `story/render.py` | оркестратор всех шагов |
| `story/orclient.py` | единственный клиент OpenRouter: текст/картинки/видео |
| `cli.py` | точка входа |

### Инвариант, который нельзя ломать

Длина i-го шота `d_i` = длина озвучки этого шота + `VOICE_TAIL_SEC`.
Видео режется до `d_i`, озвучка добивается тишиной до `d_i`, субтитры считаются
в том же таймлайне. Поэтому озвучка делается **до** заказа видео. Если поменять
порядок — голос, картинка и субтитры разъедутся, и рассинхрон накопится к концу.

### Цепочки отказов

Один заблокированный кадр не должен убивать ролик:

* кейфрейм: основная модель → она же с «чистой» оговоркой → без референса
* видео: `VIDEO_MODEL` → `SECONDARY_VIDEO_MODEL` → Ken Burns из кейфрейма

Все фолбэки логируются с уровнем WARNING — если в логе много Ken Burns, значит
контент-фильтр режет промпты, и надо править `story/prompts.py`, а не код.

## Известные места, требующие проверки на живом прогоне

1. **Слаг видеомодели.** `google/veo-3.1-fast` — предположение. Актуальный список:
   `python3 cli.py models --filter veo`. Подставить в `VIDEO_MODEL`.
2. **Кейфрейм как первый кадр.** По умолчанию уходит `data:`-URL. Часть
   провайдеров принимает только публичный http(s). Если i2v валится на кадре —
   заполнить `S3_*` в `.env`, кейфреймы поедут в R2 автоматически.
3. **Чистый низ кадра.** В промпт зашито требование не занимать нижнюю четверть.
   Модели его соблюдают через раз — если субтитр ложится на лицо, поднимай
   `CAPTION_MARGIN_V` или усиливай формулировку в `prompts.FRAME_RULES`.

## Запуск на Railway

Это НЕ веб-сервис. Контейнер делает один ролик, шлёт его в Telegram и выходит.
Домен генерировать не нужно, порт никто не слушает.

**Обязательно:** билдер должен быть **Dockerfile**, а не Railpack — Railpack не
поставит ffmpeg, и упадёт всё. За это отвечает `railway.toml`; если сервис уже
создан на Railpack, переключи вручную: Settings → Build → Builder → Dockerfile.

Переменные (Variables):

```
OPENROUTER_API_KEY, ELEVENLABS_API_KEY, ELEVEN_VOICE_ID
TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
TOPIC=тема ролика
# или TOPICS=тема1|тема2|тема3   ← берётся случайная, удобно для крона
VIDEO_MODEL, STYLE_PRESET, LANG_DEFAULT, TARGET_DURATION_SEC ...
```

Первый прогон делай с `DRY_RUN=1` — проверит ключи, сценариста и доставку
в Telegram, не тратя денег на картинки и видео. Потом переменную убрать.

Запуск: вручную кнопкой Redeploy или по расписанию —
Settings → Cron Schedule, например `0 9 * * *`.

Ошибки прилетают в тот же Telegram-чат с трейсбеком: иначе ночной крон падал бы
молча в логи, куда никто не смотрит.
